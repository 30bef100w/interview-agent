# KG场景库解释与标注规则

更新：2026-11-05。注册表版本：`2026-11-12.scene.v08`。与`backend/data/scene_registry_v01.json`和skill内置注册表同步。

## 当前场景粒度

KG按业务场景或完整应用任务匹配。黑马点评归本地生活服务，苍穹外卖归外卖服务；教程名保留为来源说明，不单设入口。简历通过业务对象和任务匹配，不要求出现教程名称。

订单、日志、风控、技术栈、页面与版本阶段不拆场景。业务相似表示可参考同类业务问题，不意味着同一项目、同一实现或同一原题来源。Redis、秒杀等通用技术不能单独证明业务场景。

本版共有79条登记，其中56个可复用入口，23条为历史映射或停用说明。原批次快照保留；登记与归类不自动补题目或知识点边。

## 标注方法

1. 先读题干及必要项目上下文，再对照业务定义、适用与排除范围。
2. 符合已有业务/应用场景就复用；只有新名称而没有独立业务任务，不新增入口。
3. 没有业务场景依据则留空；页面标题、菜名等仍为非题目。
4. 场景→题目和场景→知识点分别取证，不把场景列表与考点做交叉组合。
5. 源项目名称、出处、企业及实际实现保留为题目/来源属性。
6. 新场景核实后补入本文件与JSON注册表；旧描述确需补充时保留范围与修订依据。

### 后台管理与企业业务系统

- ID：`scene:business:admin_system`
- 使用规则：`broad_only`
- 解释：供员工、运营或管理人员处理组织内部业务的应用，常见功能包括权限、审批、配置与业务管理。
- 适用：题目明确讨论后台管理、企业内部系统或对应业务流程。
- 排除：仅问CRUD、RBAC或数据库原理，没有企业系统语境。
- 说明：仅在题干明确对应业务应用、且没有更准确项目/产品入口时使用；不是上级必经节点，不机械同时挂宽类与具体项目。；行业或泛化类别名称本身不足以给题目生成场景关系。
- 业务介绍：面向组织内部员工、运营及管理人员的业务处理系统，核心是让不同角色在权限边界内录入、审批、查询和追踪业务。与面向消费者的购物产品相比，重点常在流程一致性、数据权限和操作可追溯性。
- 主要参与者：业务员工；审核人及管理者；系统管理员
- 典型流程（示例）：身份认证与角色分配 → 提交业务数据或审批单 → 按权限流转、审核和状态变更 → 查询统计并保留操作记录
- 简历识别线索：管理后台；企业审批平台；运营工作台；RBAC与数据权限
- 可讨论方向（示例）：角色与数据权限如何协同；审批状态、并发更新与幂等；操作日志、审计与异常补偿
- 业务边界：单问CRUD、角色表或日志原理不足以确定此场景；这些只是可能的工程考点。
- 说明依据：场景语义说明与典型业务示例；不是对任何源项目已实现能力的断言。
