知识库打分与过滤

knowledge_retrieval.py 加载 12,287 道去重面经，对每道题执行多维打分，过滤噪音后取 Top-N 候选池。

  • 岗位门槛（roles 硬过滤）：主标签 +80，次标签 +35，关键词命中 +12×
  • 企业权重：目标企业真题 +120（最高优先级）
  • 场景加分：有岗位时 ×15，无岗位时 ×40
  • 技能文本命中：+4~10 / 个
  • 时效权重：2025-26 ×1.0 → 2023-24 ×0.7 → 2021-22 ×0.4 → ≤2020 ×0.2
  • 基础题降权："是什么？"结尾 ×0.3；弱标签噪音题归 0

2

双路召回策略

build_project_chains() 根据是否有目标岗位走不同检索路径，确保素材与岗位考察视角对齐，而非拘泥于项目原技术栈。

  • 路径 A（有目标岗位）：先检索岗位相关 project 类题，再检索岗位通用题
  • 路径 B（无目标岗位）：按项目名/技术栈/场景直接匹配
  • 两路合并去重，最多取 8 条素材进 LLM prompt

素材组装为 material_lines

检索命中的题目去重后格式化为结构化文本行，作为 LLM prompt 的【相关面经】输入块，给模型提供真实高频面试题作为参考锚点。

  • 每条格式：- 题目文本（要点：answer 前 100 字）
  • 最多注入 8 条，避免 prompt 过长
  • 无命中时显示（无命中），LLM 依然生成链（纯推理模式）
project_cross.py · 素材格式化
seen = set() material_lines = [] for h in hits: q = h.get("question") if q in seen: continue seen.add(q) ans = (h.get("answer") or "").strip() material_lines.append( f"- {q}" + (f"（要点：{ans[:100]}）" if ans else "") ) # 注入 prompt user 段 "【目标岗位相关真实面经/高频题】\n" + "\n".join(material_lines[:8])
4

LLM 生成拷打链

PROJECT_CHAIN_SYSTEM prompt 以「目标岗位定方向，项目只是素材」为最高原则，要求 LLM 把项目经历拧到岗位视角，生成 4-6 条由浅入深的追问链。

  • 输入：项目名 + 技术栈 + 描述 + 场景标签 + 岗位提示 + 8 条面经素材
  • 输出：JSON {"project":…, "chains":[{trigger, question, intent}]}
  • 失败容错：单项目异常直接跳过，不阻塞其他项目和整个面试
  • 每条链包含：触发条件 / 追问问题 / 考察意图
PROJECT_CHAIN_SYSTEM（节选）
# 最高原则 "【目标岗位定方向，项目只是素材】" "不要按项目原技术栈出工程专项题；" "要把项目拧到目标岗位的考察点上。" # 链结构 { "trigger": "候选人提到 X 时触发", "question": "顺着 trigger 的具体追问", "intent": "面试官想考什么" } # 目标搜广推 + 校园二手项目 # → 问样本/特征/召回/排序，不问 Redis 击穿
5

注入面试 prompt

chain_block_for() 取出某项目的链，格式化为面试官 prompt 文本块。候选人答到触发词，面试官直接顺链追问，无需即兴发挥。

  • 触发机制：候选人提及某技术点 / 关键词 → 匹配链的 trigger
  • 追问：直接使用链中 question，深度可控
  • 考察意图对面试官可见，不暴露给候选人

核心设计原则

拷打链的本质是「岗位视角的结构化追问脚本」。知识库提供真实高频面试题锚点，防止 LLM 凭空发挥；目标岗位提示确保拷打方向始终服务于岗位能力评估，而非复现项目技术栈。这使面试官在候选人随机发挥时仍能可控地深挖到关键考点。

RAG 辅助生成 岗位视角优先 结构化追问 触发 → 追问 → 意图 失败容错跳过 ≤3 项目 · 4-6 条/项目
