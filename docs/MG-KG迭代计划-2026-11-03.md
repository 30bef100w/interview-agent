# MG/KG 离线图与检索迭代计划

日期：2026-11-03。

当前优先顺序：**先固定标注与离线建图流程，再设计检索，最后评测。** 既有离线实验是临时检索原型的诊断，不作为MG/KG最终方案的效果结论。

## 1. 已确定的设计

| 内容 | 约定 |
| --- | --- |
| MG | 知识目录、原题、原答案与来源，保留企业、岗位、年份等属性 |
| KG | 项目就是场景入口，直接连接相关知识点与有明确项目归属的题目 |
| 共享实体 | MG/KG共用Concept和Question ID，不复制两套Redis节点 |
| 层级 | 知识点允许多父；题目允许挂多个知识点及非叶子节点 |
| 关系 | 细分、主题覆盖、实际考察、前置依赖、场景涉及、场景直接题分别表达 |
| 去冗余 | 合并语义相同的节点；不因题目少而删节点，不把不同范围的概念强行合并 |
| 标注与建图分工 | AI逐题判断并批量输出明确关系；脚本校验和确定性落图 |
| TG | 尚未实现，先记录真实追问链与经验积累思路，不纳入本轮实现 |

详细设计见[三图设计与标注流程](MG-KG-TG三图设计与标注流程-2026-11-03.md)，关系定义与验收规则见[离线建图与题目标注规范](MG-KG离线建图与题目标注规范-v1-2026-11-03.md)。

## 3. P0：把离线图和标注流程做实

### P0-1 固定知识点注册表

先核对同义项、中文名称、定义范围与父子关系；同一节点允许多父，不复制实体。标注每批题前先查看相关层级，再检查全局名称和别名；索引中确实缺少独立概念才提出新节点。

交付：指定版本注册表、中文目录、别名/合并映射、节点变更依据。节点提案与正式索引分开存储，不能按英文ID前缀自动推断层级。

### P0-2 按新协议复核已有题，支持后续新增题

使用[题库语义标注skill](../skills/annotate-interview-questions/SKILL.md)：固定源快照、索引版本和题目ID，逐题阅读、批量输出，区分实际考察与前置依赖。优先处理上下文不足、多场景、节点新增和语义歧义记录；已有标注作为底稿，不全量推倒重写。

场景归属必须有题干或明确项目上下文支持。不能因Redis与秒杀共现推断黑马点评；不能把项目列表与知识点列表交叉组合生成关系。

交付：annotations.jsonl、必要的节点提案与索引增量、manifest.json。清单记录计划范围、实际完成范围、状态与复核阶段，支持断点续做。

### P0-3 适配确定性建图脚本

脚本只读取已明确判断的关系，补齐REQUIRES支持，移除按编号猜父级与场景共现自动连边的历史逻辑。审核状态来自实际记录；待处理题的各类挂载状态保持一致。企业等来源属性保留，来源记录不能丢失。

交付：适配后的构建入口、新版本离线图、版本与来源清单、结构校验结果。检查节点唯一、端点合法、无悬空引用、层级无环、合并映射一致与来源完整。

### P0-4 展示真实子图并验收

按知识点和项目分别导出真实子图，使用中文名称显示、稳定ID定位，保留边含义。检查同一知识点是否被重复创建、项目关系是否有依据、考点与依赖是否混淆。

验收重点是明确关系与语义质量，不以节点少、边少或每个节点题目多作为正确标准。格式校验通过不等于所有标签已经标对。

## 4. P1：确定并实现检索方案

2026-11-06已实现可独立运行的纯图检索模块，当前参数与流程见[架构与实现](MG-KG图检索架构与实现-v1-2026-11-06.md)。下表保留生产接入与效果验证事项；结构排序、当前面试模型语义重排、岗位门禁和生产主链路适配已实现，见[接入记录](MG-KG主链路接入记录-2026-11-06.md)。

| 环节 | 实现与验证内容 |
| --- | --- |
| 结构化画像与入口 | 从简历项目和当前练习意图定位场景/知识点ID，处理同名与缩写歧义；例如React与ReAct不能混淆 |
| 路径约束 | 项目直连题、项目涉及知识点、知识层级下钻分别处理；不能从共享题任意漫游到其他项目 |
| 动态预算 | 限制深度、分支、候选数与总展开量；分支多时每支少取，分支少时多取，起始配额与总预算以v1方案为准 |
| 去重与历史 | 按题目身份去重并保留多条命中依据；历史已问题按用户/会话保存，不能在共享图上写全局“已访问”状态 |
| 适用性过滤 | 区分来源岗位与适用岗位/语言依赖，核查有效短题、多岗位题是否被旧规则误删 |
| 排序 | 区分场景原题、精确考点题与扩展补充题；结合意图、路径与内容相关性，避免共享几个技术词就反复减半 |
| 缺失处理 | 指定项目没有题时明确识别缺失；通用补充题与同项目原题分别标识 |

窄知识点查询未必需要扩展；项目准备或宽主题覆盖才可能受益于下钻。是否加入其他检索通道另行比较，不作为建图的前提。

交付：检索设计文档、参数与路径约定、可复现离线实现，再决定生产接入。

## 5. P2：评测与接入

固定相同数据快照，在独立查询上比较旧标签、AI细标签平铺和图检索。分别检查：

1. 数据覆盖：目标项目或知识点是否有真实适用题。
2. 入口：是否定位正确实体，是否识别项目缺失。
3. 候选：图关系带来了哪些新增相关题、漏掉哪些题。
4. 排序：已召回的好题是否进入前列，是否被无关扩展挤掉。
5. 任务效果：同项目原题命中、通用技术补充、宽主题覆盖分别计分。

已有20条查询作为开发回归保留，不反复调到高分后当作独立效果证明。未判候选保持未知；没有全库相关题标注时不声称测得全库召回率。争议判分需要独立复核。

如果图只在部分任务优于平铺，就只在相应任务展开；如果没有稳定收益，保留图作组织与解释，不强制替换所有召回。

## 6. 从新拉取题库到图的复用方式

```text
新增源数据（保留原文与来源）
  → 固定快照、记录身份与当前索引版本
  → AI按skill逐题判断，按批次输出标签与关系
  → 核查新增节点、别名与合并，发布索引增量
  → 校验协议、引用、计划覆盖与层级环
  → 适配后的脚本按明确关系建图
  → 中文目录、真实子图与质量检查
```

skill包含输出协议、语义判例和不依赖第三方库的格式校验脚本，可读取仓库外另行提供的题库与索引。原题库、个人数据、完整离线图快照不随本次文档与skill发布；仓库中的输入定位说明指向已有本地快照，换机器时需要显式提供对应数据，不代表这些数据已随Git提交。
