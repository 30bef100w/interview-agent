# 把题库交给码道AI标注

协作分支：[feat/mgkg-retrieval-eval](https://github.com/30bef100w/interview-agent/tree/feat/mgkg-retrieval-eval)。这套流程使用普通Markdown说明、文件和Python，协作者可以直接在华为云码道中让AI读取说明执行。

## 先拿到两个东西

1. 克隆上述分支，或在已有项目中切到该分支并更新。
2. 向分配者取得`interview-agent-annotation-remaining-36033.zip`，在仓库根目录完整解压。题库源数据保持在被Git忽略的data目录，不上传到公开仓库。数据包内包含固定批次、原题/答案/企业/来源、场景说明、知识索引和必要的全库上下文。

原始题库45,033条，已处理9,000条保持不变；剩余36,033条分为361批：B0001至B0360每批100条，B0361为33条。分配者给每个人不同的批次编号，例如甲负责B0001–B0010，乙负责B0011–B0020。F编号沿用原始全库行号，跳号正常，不代表漏题。当前是准备好的待标注任务，不能说已完成36,033条标注。

知识索引共2,346个节点，草稿身份保留，复用节点需读定义与父路径。新场景必须维护解释和匹配边界，业务模块不拆成新项目；通用技术题允许没有场景。公司信息保留在源记录中。

## 把这段话发给码道AI

把下面的B0001换成分配到的编号即可；也可以明确指定一个连续批次范围。

```text
请在当前interview-agent仓库中完成任务B0001。
先完整阅读 skills/annotate-interview-questions/SKILL.md 和它指向的 references/collaboration.md。
任务文件是 data/annotation_collaboration/2026-11-06-remaining-36033/tasks/B0001/task.json。
按任务的固定源数据与索引逐题语义标注，不按关键词自动套标签，不修改原题或原计划，不处理其他人的批次。
你自行选择可用的Python 3.10+运行检查，完成annotations.jsonl、manifest.initial.json以及必要的节点/场景变更。
初标只声明initial，实际读过多少就报告多少；全部100条输出并通过引用和覆盖检查后，报告结果与文件位置。
```

模型由协作者在码道中自行选择，流程没有写死5.6、Codex、供应商API或付费密钥。建议让AI一次读25–50题；如果上下文不足，先保存已完成记录与范围，再在新会话接续真实未完成的ID。

## 标完再开一个新AI会话检查

把任务交给新的AI会话可减少沿用初标结论的偏差，不需要更换开发工具。发这段话：

```text
请使用 skills/review-interview-annotations/SKILL.md，复核任务B0001。
任务文件是 data/annotation_collaboration/2026-11-06-remaining-36033/tasks/B0001/task.json。
不要假定annotations.jsonl是正确答案。重新读每条原题和必要上下文，再查知识点定义和场景库，检查状态、考点、依赖、场景及场景知识边。
保留初标，另写reviewed_annotations.jsonl、逐题reviews.jsonl、manifest.reviewed.json、validation.reviewed.json和简短review_report.md。
运行skill中的覆盖、原文引用和复核改动检查。脚本通过不等于语义正确；只报告实际复核数量和已解决问题。
```

有问题就让AI按错误信息回到原题修正，再检查。不能通过改计划、补假的复核标记或删除校验来消除报错。新知识点不能重复造已有同义节点；不能把找不到细节点的明确技术题全部留空。真正缺必要上下文的记录可以隔离，别编造对象或答案。

## 完成后交回什么

将自己任务目录打包交回分配者，包含原有task/source、初标、复核结果、逐题日志、两份manifest与检查结果，以及实际产生的node_proposals/index_changes/场景MD和JSON。不要上传整个源题库到公开GitHub，不用git add -f绕过忽略规则。

分配者用以下命令核对分片覆盖与实际输出；替换为本机可用的Python命令：

```bash
python3 skills/annotate-interview-questions/scripts/summarize_collaboration.py --bundle data/annotation_collaboration/2026-11-06-remaining-36033 --out data/annotation_collaboration/2026-11-06-remaining-36033/progress.json
```

这会区分未开始、初标已写、复核已写、复核记录和检查完整。只有新会话真实逐题复核，加上检查通过，才可报告已完成标后验收；不能把文件数、准备条数或声明字段当作模型读题证明。

各批新节点和场景增量最后统一去重、合并。协作者维护自己的场景副本，不互相覆盖共享库。通过后才能安排新版MG/KG建图，不自动改变原有9,000条图、草稿状态或线上检索。

范围与输入指纹见[任务计划](annotation-collaboration/task-plan.json)。工具和两个skill都在协作分支；公开计划不含原题正文。
