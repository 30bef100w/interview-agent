# 后端设计：问题与修复记录

## 2026-10-22：应用可靠性与安全边界修复

状态：代码实现与本地回归已完成；线上尚未部署，远端 CI 结果以 GitHub Actions 为准。原始基线为 `fd95ff2`。
本轮没有改动 Agent 的规划、检索、追问、评分算法或 Prompt。

### 1. 认证和管理员授权（F01～F04、F11）

#### 飞书回调缺少认证字段时放行

- 根因：原来只验证“已提供”的签名/token，缺失时跳过。
- 修改：`services/feishu_events.py` 在未配置认证时拒绝回调；token 模式要求匹配 token；Encrypt Key 模式强制签名、时间戳、nonce，验原始请求体并检查 5 分钟时间窗口；恒定时间比较、签名格式和无效编码校验。URL 验证同样受保护。
- 验证：合法 token、合法加密签名仍通过；缺失/错误凭证、未配置认证、过期签名被拒绝。
- 边界：本轮没有改造飞书事件的跨进程、持久化抗重放；仍需用真实飞书测试应用验收，不直接向线上伪造请求。

#### 按用户名自动提权、降权后再次升权

- 修改：注册、登录、HTTP 鉴权不再同步管理员标记。`ADMIN_USERNAMES` 仅作为公开注册的保留名；旧兼容函数不再提权。新增 `app.manage_admin`，在受信任主机按用户 ID 显式授予/撤销角色，并在同一事务写管理日志。
- 验证：保留名注册返回 409；已降权的配置名访问 `/auth/me` 不会重新升权。
- 兼容：已有管理员标记保留，部署前应核验已有管理员列表；该修复不会自动撤销历史上可能误授的角色。

#### 改密后旧 JWT 仍然有效、WS 未检查封禁

- 修改：JWT 增加由密码哈希和服务端密钥计算的 HMAC 版本标记，不向客户端暴露密码哈希。HTTP 与 WS 共用 `authenticate_token`，校验账号存在、密码版本和禁用状态；WS 建连、消息/心跳及答题工作线程再次校验，无消息时每 60 秒检查。
- 验证：改密后旧凭证的 HTTP 与 WS 都拒绝；已连接账号被禁用后下一条消息被拒绝。正常登录仍使用原有有效期，网页无需保存明文密码。
- 边界：这不是完整的多设备会话中心。退出登录仍主要清除本地凭证；已获授权、正在执行的外部模型调用不会被立即取消。

#### 密码字符数与 bcrypt 字节边界不一致

- 修改：注册和管理员重置密码共用 UTF-8 72 字节校验；登录验证安全处理过长或异常输入。拒绝而非截断密码。
- 验证：73 个英文字符、25 个汉字、19 个锁 emoji 被 schema 拒绝，不再进入哈希阶段产生未处理异常。
- 取舍：保留 bcrypt，未进行全量哈希迁移；未来改用其他算法时须兼容旧哈希。

### 2. 长连接和数据库生命周期（F06）

- 根因：WS 握手查询后持有 Session，等待消息期间一直占用池连接。
- 修改：快照、认证用独立短生命周期数据库 Session；同步查询在线程中运行，返回前关闭 Session，再等待网络消息。SSE 请求的读事务也在进入流式等待前释放。
- 验证：真实本地 WS 配合容量为 1 的 QueuePool，快照和心跳后 `checkedout() == 0`；保持连接时其他数据库查询可用。
- 边界：这只解决空闲连接占用。正在执行的模型/数据库工作仍需要资源，尚未完成 PostgreSQL 真实容量和大规模压测。

### 3. 单场额度和失败退款（F07）

- 根因：创建成功后才扣次，检查和扣减分离；已开场后又检查“还能否开新场”。
- 修改：创建会话与扣次同事务，使用 `UPDATE ... WHERE platform_quota > 0` 原子预占；会话记录 `billing_source` 和 `quota_state`。规划成功确认消耗，失败通过条件更新退回，退款与额度流水同事务。
- 修改：后续答题认可本场的预占/已消费权益，不因账户余额已变为 0 而拒绝。网页和飞书创建入口共用预占。自填 Key 创建的场次不能通过清空 Key 静默切到平台资金来源。
- 验证：余额 1 可以创建、规划成功并继续获取引擎，余额保持 0；第二次预占被拒绝；重复退款仅一条 +1 流水。
- 兼容：旧活跃/已结束会话保留 `legacy` 兼容访问；新场严格走新规则。管理员发放/绝对设置额度的完整并发审计仍需进一步加强。

### 4. 提交幂等、并发和过期工作线程隔离（F08）

新增 `services/interview_operations.py` 和 `interview_operations` 表：

1. 客户端发送 `submission_id` 和 `expected_version`。
2. 服务端校验资源归属、请求内容指纹、会话版本，以短事务原子认领本场处理权；不在模型调用期间持有用于认领的行锁。
3. HTTP、SSE、WS、代码提交、退出和飞书答题共用该入口，处理中其他命令返回 409。
4. 会话状态、回答/报告、当前事务中的用量及最终响应一起提交。成功编号重试返回保存的结果；相同编号不同内容拒绝。
5. SQLAlchemy 版本列阻止旧工作线程覆盖新状态。中断标记有 20 分钟截止时间；恢复扫描释放过期标记并提升版本，旧工作线程不能再提交覆盖。

验证：同一编号依次通过真实 HTTP/SSE/WS 入口，仅推进一次并生成一条问题记录；不同通道被处理中标记拦截；失败回滚、旧版本拒绝、过期工作线程提交被拒绝。

边界：旧客户端不传编号时仍兼容，但无法识别“处理完成后的顺序重复请求”。飞书事件的跨进程去重、创建会话本身的请求幂等、数据库业务唯一约束仍需另行完善。外部模型计费无法与本地事务原子提交，进程崩溃后不能承诺不产生任何外部重复费用。

### 5. 被中断的创建任务有明确终态（F09，部分完成）

- 新创建持久化 20 分钟 deadline。每个服务进程启动恢复扫描，并每 60 秒扫描过期创建与提交；查询创建进度时也检查创建超时。
- 创建失败先 rollback，再条件更新 `creating → failed` 并退回预占。只有仍在 creating 的任务会失败，不会因规划成功后的日志异常把活跃会话改成失败。
- 旧库仍在 creating 的会话在升级时补一个恢复窗口；旧场没有新预占记录，不会凭空退款。
- 验证：模拟任务被中断后重新扫描，状态转 failed、次数只退一次；重复扫描不再更改结果。
- 未完成：不是持久化任务队列，不会自动重放规划请求，也不承诺从模型生成中间位置续跑；生产需要按业务目标继续建设任务参数持久化、租约/心跳和重试。

### 6. 过载告警不能拖住核心请求（F10）

- 原来 async 中间件直接执行同步通知网络 I/O，失败时后续请求可能继续尝试。
- 现在请求路径仅计数并尝试启动一个有并发上限的通知线程；同一进程只允许一个在途告警，失败也按冷却窗口退避。滑动窗口改用 deque。
- 验证：阻塞通知发送函数时请求侧调用能返回；在途及失败冷却期内不新增发送。
- 边界：不是全局限流，也不是多实例统一监控；大量流量下仍需网关和应用级配额。

### 7. 用户 Key 无法解密时停止，而不是转平台 Key（F12，部分完成）

- 修改：密文损坏/密钥轮换导致解密失败返回可读 409，要求重新配置；显式自填模式没有 Key 也拒绝，不再将空字符串传给默认客户端兜底。
- 验证：损坏密文不能解析出平台调用配置。
- 未完成：简历分析等所有 AI 功能的配置来源与计费入口尚未完全统一，独立加密密钥及其轮换也仍待建设。

### 8. 前端与后端协议衔接（F15～F20）

| 问题 | 修改 |
|---|---|
| 网络/500 导致误退出 | AppShell 和管理后台仅对明确的 401/403 清凭证，过期请求不能覆盖当前登录；后台校验可重试，简历列表错误不再全部跳登录 |
| 简历 A 的结果写到 B | 选择实体 ID 校验、列表按 ID 更新；画像编辑版本保护；保存/删除不抢占新选中项，复盘请求加序号 |
| 答案发送失败丢原文 | 不在发送前清空；收到最终确认或快照中的匹配提交编号才清理 |
| 代码刷新/切换语言丢失 | sessionStorage 草稿按用户/会话/题目/语言/模式隔离，模板更新可恢复；面试切换时编辑器 key 包含会话 ID |
| 发送中 WS 断线不恢复 | 中断时明确提示未知结果，允许重新连接拉快照；不盲目重放答案，清理重连与等待定时器，认证拒绝不循环重连 |
| SSE 无终态时一直等待 | EOF 无 done/error 视为未确认；处理 CRLF/分块、终态停止读取、格式异常可见、释放 reader，并设置等待上限 |
| 422 显示 `[object Object]` | 统一解析字段错误，HTTP/SSE 共用错误转换 |
| 跨账号本地通知与偏好串用 | 通知、默认简历、新手引导按 JWT 用户 ID 命名空间存储；不迁移归属不明的旧全局数据 |
| 页面离开后仍被旧任务跳转 | 规划轮询可取消，卸载或失效请求不再导航 |

草稿保留策略：当前标签页会话存储，7 天 TTL；刷新/组件重挂载可恢复，不保证浏览器清理、关闭标签页或跨设备恢复。存储不可用时保留内存编辑能力。
新增 Node 测试覆盖错误转换、用户隔离、过期清理、SSE 异常终止、WS 重连与定时器清理；组件竞态与所有浏览器视觉仍需 E2E 验收。
手机代码区改为窄屏单列；导航、外部编辑器 CDN 和字体资源等 F21 其余部分未完成。

### 11. 部署和兼容要求

1. 先备份数据库与上传文件，保留可恢复的旧代码版本；不要直接以测试通过代替备份。
2. 先停止旧后端工作进程，按现有 `create_all + ensure_schema` 做单实例结构升级，再启动新代码；新旧版本不能混跑。新增表及列已有旧 SQLite 补列回归，但尚未用真实 PostgreSQL 验证。
3. 新 JWT 要求密码版本标记，旧凭证统一失效，用户重新登录一次。之后正常保持登录的有效期不变。
4. 管理员不再自动按名字升权；核验现有管理员。新建首位管理员使用受信任服务器的 `python -m app.manage_admin --user-id 实际ID`。
5. 飞书回调必须配置正确的验证 token/Encrypt Key，并在飞书测试应用中验证合法事件和 challenge；未配置时入口拒绝。
6. `billing_source=legacy` 的旧会话为兼容模式；不要批量伪造新预占记录或对旧场重复扣费。
7. 发布后检查 `/api/ready`，再用测试账号走一遍注册/登录、简历、创建、答题、代码提交、报告、断线恢复及失败退款。
