# 深问 — 可观测性与兜底（开发与运维文档）

> 配套：`设计文档-后端与Agent.md`、`deploy/README.md`  
> 对齐代码：`observability/`、`session_guard_log.py`、`create_timing_log.py`、`feishu_notify.py`、`session_checkpoint.py`、`interviewer_engine.py`

---

## 0. 设计原则（一句话）

**可观测性**：轻量落盘 + Admin 查询 + 可选飞书告警，不做 Prometheus/Grafana。  
**兜底**：控制面在引擎；LLM/外部依赖失败走降级链，**不改整场题单剧本**，优先保证「能考完」。

```text
用户请求
  ├─ TraceMiddleware → X-Trace-Id
  ├─ 业务（创建 / 答题 / WS）
  │    ├─ logs/create_trace/{id}.json      规划分步耗时 + 前端进度条
  │    ├─ logs/engine_trace/{id}.jsonl     引擎节点 trace
  │    ├─ logs/session_guard/{id}.jsonl    兜底 / 门禁事件
  │    ├─ Redis / logs/session_checkpoint  弱网快照
  │    ├─ metrics_registry（进程内）        节点 / LLM 计数与耗时
  │    ├─ system_logs（DB）                 未捕获异常
  │    └─ llm_usage（DB）                   Token / 费用
  └─ 查询：Admin 页 / Trace API / 飞书 Webhook
```

## 1. 可观测性

### 1.1 HTTP 层：`trace_id`

| 项 | 说明 |
|----|------|
| 文件 | `backend/app/middleware/trace_middleware.py` |
| 行为 | 每个 HTTP 请求生成或透传 `X-Trace-Id`（16 位 hex） |
| 日志 | 未捕获异常写入 `app.trace`，带 `path` + `trace_id` |
| 注意 | SSE/WS 后台线程需单独 `set_trace_id`（中间件管不到子线程） |

**用途**：把某次 API 报错与 `engine_trace` 行对上号。

---

### 1.2 创建阶段 trace：`create_trace`

| 项 | 说明 |
|----|------|
| 文件 | `backend/app/services/create_timing_log.py` |
| 落盘 | `backend/logs/create_trace/{session_id}.json` |

开练时后台异步规划，每走一步 append 一条 step：

| step | 含义 |
|------|------|
| `begin` | 开始创建 |
| `opening_llm` | 开场白 LLM |
| `plan_retrieval` / `retrieval_role_filter` | 多路召回 |
| `project_chains` | 拷打链生成 |
| `router` | 项目/八股比例 |
| `build_plan` / `planner_llm` / `bagu_inject` | 出题单 |
| `engine_done` / `finish` | 完成 |
| `failed` | 规划失败 |

**消费者**：
- 前端开练进度条：`GET /api/interview/session/{id}/create-progress`
- Trace API 合并进 `timeline`

---

### 1.3 引擎节点 trace：`engine_trace`

| 项 | 说明 |
|----|------|
| 文件 | `backend/app/observability/node_trace.py` |
| 落盘 | `backend/logs/engine_trace/{session_id}.jsonl`（一行一个节点） |
| API | `trace_node("节点名", session_id=...)` 上下文管理器 |

每次 `trace_node` 会同时：
1. 写内存 metrics（次数、耗时、错误）
2. append JSONL（`ts / trace_id / node / duration_ms / outcome`）
3. 打 `app.trace` 日志

**已埋点节点（主链路）**：

| 节点 | 阶段 |
|------|------|
| `plan_retrieval` | 创建时召回 |
| `build_plan` | 规划出题单 |
| `handle_intro` | 自我介绍后进第一题 |
| `follow_up_and_score` | 追问判断 + 评分（并行 LLM） |
| `score_sanitize` | 分数 / 优点消毒 |
| `question_summary` | 单题小结 |
| `ask_question` | 口头出题 |
| `finish_interview` | 终评报告 |

**说明**：对标全链路 APM 尚未铺满（例如每次 `chat_json` 未单独成节点），但面试主路径已覆盖。

---

### 1.4 进程内指标：`metrics_registry`

| 项 | 说明 |
|----|------|
| 文件 | `backend/app/observability/metrics.py` |
| 特性 | 内存聚合，**进程重启清零** |
| 节点 | `count / errors / avg_ms / p95_ms` |
| LLM | `llm.calls / llm.errors`，并按 `llm:{model}` 分桶 |

**查看**：管理员 `GET /api/observability/metrics` → 前端 `/admin/observability`

**没有**：Prometheus 拉取、跨实例历史趋势大盘。

---

### 1.5 兜底 / 门禁事件：`session_guard`

| 项 | 说明 |
|----|------|
| 文件 | `backend/app/services/session_guard_log.py` |
| 落盘 | `backend/logs/session_guard/{session_id}.jsonl` |
| 函数 | `log_guard(session_id, event, **detail)` |

与 trace 互补：**trace 看耗时，guard 看为什么走了旁路**。

| event | 含义 | 触发位置 |
|-------|------|----------|
| `create_failed` | 后台规划整段失败 | `api/interview.py` |
| `fallback_plan` | 规划结果为空，启用内置题单 | `interviewer_engine._build_plan_body` |
| `planner_llm_failed` | 规划官 LLM 异常 | `interviewer_engine._build_plan_body` |
| `llm_filter_empty_kept_original` | 岗位过滤后为空，保留原召回 | `interviewer_engine._filter_hits_by_llm` |
| `llm_filter_degraded` | 岗位 LLM 过滤失败，跳过过滤 | 同上 |
| `project_chain_empty` | 某项目拷打链为空 | `project_cross.py` |
| `project_chain_skipped` | 拷打链 LLM 异常，跳过该项目 | 同上 |
| `score_capped` | 空答 / 敷衍，分数被引擎压顶 | `interviewer_engine` 评分后 |
| `strengths_cleared` | 优点与作答无关，被清空 | 同上 |
| `non_answer_no_followup` | 空答强制不追问 | 同上 |
| `followup_repeat_rejected` | 追问与已问重复，丢弃 | 同上 |
| `ask_question_retry` | 出题撞历史 / 空泛编排，重出 | `interviewer_engine._ask_question` |
| `resume_claim_sanitized` | 简历幻觉句被改写 | `interviewer_engine._sanitize_resume_claim` |

### 1.6 合并查询：Trace API + 时间线页

| 项 | 说明 |
|----|------|
| API | `GET /api/observability/sessions/{id}/trace` |
| 权限 | **仅管理员**（`require_admin`） |
| 实现 | `backend/app/api/observability.py` |

返回四块：
- `create_trace` — 规划 JSON
- `engine_trace` — 引擎 JSONL
- `guard_events` — 门禁 JSONL（最近 80 条）
- `timeline` — 三者按时间合并排序

**前端**：`/admin/observability`（会话 Trace 查询）或 `/admin/observability/sessions/{id}`（独立时间线页）

|----|------|

### 1.12 日常排障速查

| 你想查什么 | 去哪 |
|-----------|------|
| 某场规划卡在哪一步 | `logs/create_trace/{id}.json` 或开练进度条 |
| 某场答题慢在哪个节点 | `/admin/observability/sessions/{id}` |
| 为什么没追问 / 分数很低 | `guard_events` 里 `non_answer_no_followup`、`score_capped` |
| 线上 500 | Admin → 系统日志；或 `interview.log` |
| LLM 花了多少钱 | Admin 统计 + `llm_usage` 表 |
| 规划批量失败 | 配飞书 Webhook；搜 `create_failed` |
| 题库标签错了 | Admin 错标审核 + 满批飞书 |

## 2. 兜底机制

兜底分三层：**规划阶段**、**答题阶段**、**基础设施**。

设计原则：**一次规划 + 多层降级**；不根据中途表现重规划整张题单。

### 2.1 规划阶段（开练时）

```text
召回 → LLM 岗位过滤 → 规划官出题单 → 八股注入 → 去重补齐
         ↓失败/全删光              ↓失败/为空
      保留原召回              fallback_plan 内置题单
```

| 机制 | 行为 | guard event |
|------|------|-------------|
| LLM 岗位过滤成功 | 剔除串岗题，剔除的进 `tag_mismatch` 队列 | — |
| 过滤后为空 | **保留原 hits** | `llm_filter_empty_kept_original` |
| 过滤 LLM 异常 | **整段跳过过滤** | `llm_filter_degraded` |
| 规划官 LLM 失败 | `raw_questions = []`，靠八股注入 + 补位 | `planner_llm_failed` |
| 最终 `plan` 仍为空 | `_fallback_plan(mode)`：尽量从八股库抽 1 道 + 占位项目/HR 题 | `fallback_plan` |
| 八股瀑布 | 企业×岗位 → 企业不限岗位 → 其他企业 → 无标签 | — |
| 去重后空位 | `_top_up_plan` / `_regenerate_project_items` 按题型补位 | — |
| 创建整段失败 | `session.status = failed` + 飞书（可选） | `create_failed` |
| 拷打链为空 / 异常 | 跳过该项目或记空链 | `project_chain_empty` / `project_chain_skipped` |

**八股瀑布**（`pick_bagu_questions`）：保证「选了字节」不会用别家题凑数（硬过滤履约）。

---

### 2.2 答题阶段（面试进行中）

| 机制 | 行为 | guard event |
|------|------|-------------|
| 空答检测 `is_non_answer` | 「下一个/不会/跳过」等 → 分数封顶 ≤1，**强制不追问** | `non_answer_no_followup`、`score_capped` |
| 评分消毒 `sanitize_score_fields` | 优点必须与作答有文字重叠，否则清空 | `strengths_cleared` |
| 追问去重 | 与本轮已问题干高度重复 → 丢弃追问 | `followup_repeat_rejected` |
| 追问上限 | 每题最多 `MAX_FOLLOW_UPS`，总轮次 `total_rounds` 封顶 | — |
| 出题重试 | 撞历史问法 / 空泛编排题 → 让 LLM 重出一道 | `ask_question_retry` |
| 简历幻觉 | 题干假称「简历写过」→ 改写 | `resume_claim_sanitized` |
| 算法题 | 本地对拍判 AC/WA，不依赖模型 | — |
| 流式双通道 | WS 优先，失败回落 SSE | — |

---

### 2.3 基础设施兜底

| 点 | 做法 |
|----|------|
| Redis checkpoint 挂了 | 写本地 JSON 文件 |
| 飞书 webhook 未配 | 静默跳过 |
| 生产 JWT 默认值 | 启动 `RuntimeError` 拒绝起来 |
| 平台 Key 额度用尽 | `assert_platform_allowed` 禁止新建会话 |
| 全局未捕获异常 | 写 `system_logs`，返回 500 通用文案 |

## 5. 新增兜底 / 观测时的开发约定

1. **新兜底路径必须 `log_guard`**，event 名用 snake_case，语义稳定可 grep。
2. **耗时节点用 `trace_node`**，命名与 `create_timing_log.step` 保持一致风格。
3. **LLM 调用**经 `OpenAiLlm`，自动记 `record_llm` + `llm_usage`。
4. **不要**在 guard 里抛异常；写日志失败也不应阻塞主流程。
5. **飞书告警**只用于运维可操作事件，不做用户侧通知。
