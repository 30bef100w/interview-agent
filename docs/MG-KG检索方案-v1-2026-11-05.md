# MG/KG 有界图检索方案 v1

日期：2026-11-05。**本文保留11月5日的初始方案，80题等预算为历史参数。** 11月6日按最新讨论调整为项目KG/MG双路随机BFS、最多500候选选100、八股领域叶子题池随机抽样；已实现独立模块与试跑入口，详见[当前架构与实现](MG-KG图检索架构与实现-v1-2026-11-06.md)。后续已接入面试主链路及语义重排，代码默认启用、尚未部署服务器，详见[接入记录](MG-KG主链路接入记录-2026-11-06.md)。TG尚未实现。后文历史规划不表示所有语义精排和生产接入已完成。

## 1. 固定输入，按项目检索

每次围绕一个项目或一个追问目标构造 QuerySpec：项目业务原文与出处、候选人负责内容、场景 ID、知识点 ID、当前考察机制/约束、岗位、企业偏好、已问题目及语义要点。多项目分别构造，不把不同项目的技术和场景混合成一个查询。

先通过名称、中文名和别名定位候选实体，再由模型对照定义、父路径、场景匹配条件及排除边界确认 ID。不能按字符串命中直接认定业务归属，也不根据英文 ID 前缀猜父级。模型只能选择注册表 ID，允许没有匹配项；同名异义须结合原文区分。

场景介绍中的典型流程和可讨论方向是理解辅助，不是候选人已经实现这些功能的证据。候选人没有写日志，不表示没有日志；追问可以询问日志设计，但不得断言已使用某套方案。场景无法确定时保留知识点入口，不强行套入宽泛业务。

## 2. 三条召回路径

| 通道 | 路径 | 返回题的身份 |
| --- | --- | --- |
| 场景直接题 | Scene → HAS_QUESTION → Question | 有明确标注依据的场景题；业务相同不等于相同源项目 |
| 场景知识扩展 | Scene → INVOLVES → Concept → 有限 HAS_SUBTOPIC 下钻 → 反向 TESTS 找 Question | 可用于该场景的知识补充，不能伪称该场景原题 |
| 简历知识补充 | 简历明确 Concept → 有限 HAS_SUBTOPIC 下钻 → 反向 TESTS 找 Question | 来自实际简历技能/当前问题的知识补充 |

存储方向仍为 Question → TESTS → Concept。反向查题通过查询侧入边索引完成，不为方便遍历在主图新增成对反向边。MG/KG 使用同一批知识点和题目 ID。

```text
当前项目 → 场景
             ├─ HAS_QUESTION → 已归属该业务的题目
             └─ INVOLVES → 知识点
                              └─ HAS_SUBTOPIC（0～2层）→ 知识点
                                                             ← TESTS ─ 题目
简历明确知识点 ──────────────────────── 同样有限下钻与找题
```

题目可挂在非叶子节点。每次下钻都检索当前节点的直接题，再按剩余预算访问子节点，不只在叶子找题。以细知识点为目标时允许零层下钻，不为了扩大结果强制扩展。

## 3. 路径白名单与停止条件

- HAS_SUBTOPIC 只向下，最多两层。不爬到顶层再遍历兄弟知识点。
- INVOLVES 只从当前已选场景到知识点；禁止从共享知识点反向进入其他场景。
- TESTS 反向用于找题；题目是遍历终点，不把题目提到的其他知识点继续当作扩散入口。
- REQUIRES 保留用于前置依赖解释与适用性判断，v1 不作为扩散主路。
- COVERS_TOPIC 在 v1 不展开。后续若加入，须独立做消融实验并单设预算。
- 不遍历无类型的“相关”关系，不以全图连通分量作为召回范围。

同一个知识点从多个入口到达时缓存其邻接查询，合并命中来源，避免重复展开。深度按各入口的合法路径记录，不能因为首次经较长路径访问就屏蔽另一条合法短路径；达到任一全局预算立即停止新增展开。

## 4. 动态预算

以下参数作为离线 v1 的起始配置，尚无实测性能保证。后续只在开发集调参，验收集固定后不得反复调到高分。

| 参数 | 初始值 | 含义 |
| --- | --- | --- |
| 唯一候选题上限 | 80 | 三路合并后的总上限，不是每路各取80 |
| 三路起始名额 | 24 / 40 / 16 | 场景直接题 / 场景知识扩展 / 简历知识补充 |
| 每项目场景入口上限 | 2 | 只有明确支持复合业务时才同时选择；不是强制凑两个 |
| 合并后的知识入口上限 | 6 | 场景涉及点与简历知识点共同竞争名额 |
| 知识层级深度 | 0～2 | 从各知识入口计算，不计找题那一跳 |
| 单节点子分支上限 | 8 | 先按本次目标选择相关子分支，不能依赖文件中的原始顺序 |
| 唯一展开知识点总上限 | 120 | 跨通道共享；限制中间节点量，不只限制最终题数 |
| 最终参考题上限 | 12 | 通常8～12道；不足时允许少于8道或为空 |

各通道、各相关分支先分配名额，再按相关程度调整。某支只有3道符合条件的唯一题，即使有10个名额也只消耗3个，余下名额回流给其他尚有合适题的分支。40个名额遇到4个同等相关分支时约每支10个，遇到2个时约每支20个。

分支权重来自本轮目标、简历证据和岗位适用性，不使用节点总度数或题库题量作为相关性代理。找不到更多符合条件的题就停止，不放宽业务事实、语言依赖等约束凑满80。

实现时按“每路取一批 → 全局去重与检查 → 分配剩余名额”循环，避免先拼满第一路导致后两路失效。只有新增唯一且适用的题才占名额；对同一题新增命中路径不再占名额，也不因路径多而无限加分。

## 5. 过滤、去重与企业属性

- 禁用题、无访问权限题和已撤回来源为硬过滤。缺答案允许进入选题，但不得拿空答案做事实评分依据。
- 岗位缺标不等于不适用；语言特定实现、机制和题意是否适用须结合内容判断，不能照抄旧岗位标签交集为零就丢弃的行为。
- 企业保留为题目/来源属性，只在已确认相关的候选间调整优先级。同企业不能覆盖机制不符或业务不符。
- 同题多路命中按题目 ID 合并，保留来源通道和合法路径。已确认重复簇以后使用 canonical_question_id；当前图尚未完成跨来源语义去重，不能声称不同 Question ID 都是不同语义题。
- 近似题在精排与集合选择时复核；依赖不同项目上下文的同一句短题不能误合并。时间戳只用于版本和更新，不用于判断语义重复。
- 已问内容保存在用户/会话检索状态中，不在共享图上写全局“已问”标记。相同知识点可以换角度继续追问，已经问过的同义问题不重复占名额；有意延续的深入追问明确记录意图。

## 6. 有限候选精排与模型输入

仅对上限80道候选做语义适用性判断。检查当前业务任务、目标机制、约束、候选人实际经历、岗位深度与已问内容，先剔除明显不适用项，再选择覆盖不同必要角度的题。

场景直接题不天然高于精确命中当前机制的通用题。例如当前只问缓存一致性，属于外卖业务但只考页面展示的题不应靠场景身份占据前排。路径是可解释的先验，最终须看题意能否用于本轮追问。

最终给规划官/追问官的材料包含：题目 ID、原题及必要的补全题干、相关知识点、通道、场景归属证据、命中路径、适用理由、公司/岗位来源属性、必要的原答案片段及定位、节点与边的审核状态。只装入被选题目的紧凑证据，不把整张子图、所有相邻题或整份长答案直接放进提示词。

原答案是源参考资料，不等于已验证标准答案；生成参考解和评分时仍需校验支持范围。输出过长时在提示词材料层设置独立 token 预算，保留原题和出处，长答案按本轮目标选取可追溯片段，不能截断到丢失适用条件。

## 7. 当前快照与缺失处理

当前离线快照处理9000条记录，其中8704条为题目、272条为非题目、24条待上下文；2346个知识点、39个场景、16023条边。知识点263个active、2083个draft。39个场景有详细介绍，64个常用知识点有新增概念说明，其余仍依赖已有名称、定义（如有）、路径和真实题目理解。

本地生活、外卖等入口在本批没有直接场景题。应返回MG知识补充并标明“无当前场景直接题”，不能通过相似技术倒推出场景原题。没有相关题时允许返回空结果；模型生成的假设题如另行启用，必须与题库检索结果区分。

草稿审批按用户要求暂缓。离线实验可包含draft并携带状态，同时单列active-only结果，检查严格过滤造成的覆盖损失；不得为了实验机械升为active，也不得把含草稿的结果写成正式生产知识库。

## 8. 实现顺序与验收

1. 固定快照、路径白名单、QuerySpec及以上参数，加载出入边索引；实现有界三路召回和去重，先不接生产。
2. 在真实简历/查询上核对入口、每路候选、路径和名额回流；记录展开知识点数、候选数、停止原因、耗时及精排成本。
3. 同一题库与候选/最终条数预算下，对照旧标签检索、仅MG检索、MG+KG检索，另做无精排/同一精排器对照，分离图结构与模型精排的贡献。
4. 分别评估场景直接题、可用项目追问、精确知识命中、重复率和业务/经历误归因；统计有题和无题场景，不能用通用题命中掩盖场景原题缺失。
5. 开发集与验收集按项目及近重复题簇分组，未判断候选不直接视为不相关。既有小样本A/B仅用于开发诊断，不作独立验收结论。
6. 正确性和效果达到验收条件后再考虑接入生产；以后是否添加其他检索通道由漏召回分析决定，不作为当前建图前提。

当前不宣称图检索已经优于旧检索，也不宣称已完成TG或自进化闭环。
